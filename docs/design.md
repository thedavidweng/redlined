# Design rules

- The mock is truth. Never redesign `mock/`. The only hook it may contain is the `?redline=` seam. Names stay fictional.
- Each redline is one minimal change, layered on the original through `patch.js`/`patch.css`.
- Match the product's existing colours, type, spacing and components. The result should look like the company's own next release. Restyle only when asked.
- Motion should be restrained and feel native. Use the shared ease `cubic-bezier(.32,.72,0,1)` and honour reduced motion. Shared helpers live in `<product>/_shared/`.
- Never position overlays from a single measurement taken at render time. Fonts and frame sizes settle later, especially in the stage. Re-measure with `ResizeObserver` and `document.fonts.ready`, or let CSS lay it out.
- `?state=<name>` is an extension of the `?redline=` seam, for products with several screens (iOS): it opens the mock straight into that state for calibration and recording. It only reads the URL, so without it, and in every before render, the mock is unchanged. Lime has `home`, `selected` and `sheet-expanded`. An unknown state falls back to the first one with a console warning. Modo also takes `?now=<ISO local time>` (e.g. `2026-10-12T12:11`), which freezes `ModoData.now()` so clip labels do not depend on the recording hour; without it the real clock is used.
- iOS products: a patch gets `redlinePatch.apply({ root, map, data })`: the app root, the MapLibre map and the product's data. Work through these handles and `patch.css` only. Vehicles and parking spots are map layers, so a redline that changes them edits the map's sources or layers, not DOM. For text the mock writes itself, observe the element and rewrite it (`MutationObserver`, then `takeRecords()` after your own write) rather than editing the mock or its data. Convert from the stored value; never hard-code the result (`01-fix-range-in-km` turns miles into km).
- Map credits (OpenFreeMap, OpenStreetMap) never go inside the mock, because the real app shows none. `IosDevice.credit()` puts them outside it: the page corner, the stage corner (so they are in every clip), or a five-second fade on a phone.
- No React. Introduce it only in a product whose mock grows a multi-level navigation stack or many interlinked states that vanilla can no longer keep straight. Then only in that product, with an ADR in `docs/adr/` that says how its patches work.
