# Modo Mock

A full-screen map with fictional cars inside the shared iPhone frame. Calibrated by eye against reference screenshots of the real app (`_tools/calibrate.py modo home|selected|vehicle|filter|time|booked`); not 1:1. All data is fictional (stations, plates, member number, parking text; the member name is the author's own, by choice) and the camera is in Fairview, Vancouver, north up, more than 1 km from where the references were taken.

Serve the `redlined` folder (`python3 _tools/serve.py`) and open http://127.0.0.1:4173/modo/mock/, or double-click `index.html`. The map needs a network connection (OpenFreeMap tiles, OpenStreetMap data).

## States

`?state=home` (default), `?state=selected` (tap a pin: camera recentres on it, selected marker, sheet "1 option" with a scrolling car card) and `?state=vehicle` (tap the card: Vehicle Information pushes from the right; the back chevron pops) and `?state=filter` (tap the Filter pill: the Filters sheet slides over the whole screen with a 50% backdrop; chips and checkboxes toggle, Clear All resets, APPLY only closes it and does not filter pins; the grabber, header (at the top of the scroll), backdrop and APPLY dismiss it). SET RETURN / OPEN RETURN are tappable (OPEN RETURN fades out the arrow and End Time and moves the single time left, as in IMG_7638; the vehicle page shows Return Type "Open Return" and keeps its Return by row, start + 12 h, as in IMG_7637). Start Time and End Time open the time sheet, `?state=time` (OPEN RETURN selected, as in the reference): a white sheet like Filters (50% backdrop, grabber, backdrop or CLOSE dismiss) with title, an Open Returns subtitle (open return only) and an inline wheel (date -30..+60 days, hour, minute in 15-min steps, AM/PM; hours and minutes loop, tap a row to centre it); SAVE writes "12 Oct at 4:00 PM" (IMG_7638 format) into the header and the vehicle page (an end at or before the start becomes start + 1 h), the ✕ clears both. Filter chips and checkboxes animate. Tapping empty map or dragging the sheet down returns home. Tapping a cluster zooms in. Filter, locate, the ? help and tab bar are static; BOOK VEHICLE is disabled ("Please set a time") until a range is set that is free on the selected car, then it is enabled (and never books: tapping does nothing). With times set the page also shows the Earliest/Latest Availability box under Change Time, and its rows use the page's own date format ("Mon, 12 Oct 2026, 12:15 PM"). Change Time opens the time sheet for the start time (confirmed by IMG_7636). `?state=booked`: the near car selected, page pushed, SET RETURN, start = the next quarter hour, end = + 30 min (12:15-12:45 at 12:11, the reference). The availability strip starts at the current hour and shows busy windows (crossed grey), free quarters (light blue) and your chosen quarters (navy); it redraws when the pin or times change. Quarters before the current quarter are not bookable: `window()` returns null for them and earliest is the current quarter (IMG_7634..7637 at 14:49: 2:45 PM is the earliest). When the chosen range is free they are drawn crossed grey (IMG_7637); when it is busy on that car they stay light blue (IMG_7638, IMG_7639).

When the chosen range is busy on the selected car: the card gets a red UNAVAILABLE label above the name (everything below shifts down 26 pt, the card is 23 pt taller), the car's pin turns grey (every pin that is busy in the range does; two twin layers, `pins-busy` and `pins-grouped-busy`, driven by feature state) and the busy quarters inside the range are drawn dark crossed (#434343). On the vehicle page a grey box under Change Time reads "This vehicle will be available for 12h 0m from:", the next free window "13 Oct 2026 at 3:45 PM → 14 Oct 2026 at 3:45 AM" and a navy SWITCH TO THESE TIMES button; tapping it sets the trip to that window (`ModoData.nextFree`) and BOOK becomes enabled (busy-box.png). Each pin has its own car (name, chips, plan) from `ModoData.cars`. The sheet has a single detent (`../../_ios/sheet.js` with snaps open/hidden). Durations are estimates, there is no reference video. `prefers-reduced-motion` removes the push animation and jumps the sheet.

`?now=<ISO local time>` (for example `?now=2026-10-12T12:11`) freezes the mock's clock: `ModoData.now()` defines the present everywhere (availability strip start, time sheet today and rounding, booked times, patches), so recordings do not depend on the hour. Without it the real clock is used. It combines with `?state=` (`&now=`). The stage loads every Modo clip with it: `../_shared/stage.json` puts `?now=2026-10-12T12:11` (the `booked` reference time) in the mock path.

## Where to change things

- `../_shared/data.js`: `ModoData`: camera, pins, clusters, member, `cars[n]` (name, type, seats, fuel, plan, filter `class` and `features`), `match({ classes, seats, features })` (pin numbers matching filter choices), and availability: `busy` windows per pin in quarter hours from the start of the current hour, `availability(n, now)` (busy intervals as Date pairs) and `window(n, start, end, now)` (the free `{ earliest, latest }` containing the range, or null if it overlaps a busy interval or starts before the current quarter) and `nextFree(n, from, length, now)` (the next free `{ start, end }` on the quarter grid long enough for `length`).
- `app.js`: `drawStrip` (dot looks), `render` (header, rows, BOOK state, availability box), `fill` (selected pin's car).
- `style.js`: re-tints OpenFreeMap Bright to the reference's grey Mapbox-light look (12 layers). Modo has its own style helper; there is no shared keep-list helper in `_ios/`. `markers.js`: marker images as symbol layers, selection by feature state. `app.js`: map, sheet, push/pop.
- `../../_tools/calibrate.py` reads the map handle as `<Product>Map` (`ModoMap`).

## Assets and fonts

- `Poppins-Regular.woff2`, `Poppins-Medium.woff2` (titles) and `Roboto.woff2` (body), SIL OFL, from github.com/google/fonts, with `OFL-Poppins.txt` and `OFL-Roboto.txt`. The app's own fonts are not committed.
- `assets/*.png` and `assets.js` (the same as data URIs, since WebGL cannot read file:// images) are exported from the IPA asset catalog: `availableMarker@3x`, `selectedMarker@3x`, `availableCluster@3x`, and `car@3x` (the car half of `car_bike@3x`; a generic hatchback, mirrored: the Corolla Hatchback's photo), `unavailableMarker@3x` (the grey pin). `assets/cars/*.png`: the real app's photos of the Corolla Hybrid, Prius Prime, RAV4 Hybrid, Ford Escape Hybrid and Nissan Kicks, cropped from the reference captures and trimmed of white margins (loaded as `<img>`, not in `assets.js`).
- `../_shared/icon.png`: the app icon (256 px), from the IPA asset catalog (`AppIcon`, 1024 px). The series home shows it on the product card.
- Drawn in code: availability dots (inline SVG; Chrome blocks CSS masks from file://), icons, user dot.

## Differences and gaps

- The Mapbox wordmark and the attribution (i) button are omitted; credit is OpenFreeMap/OSM via `IosDevice.credit`.
- The selected pin is visible in the map strip; in the reference it sits under the sheet.
- Availability dots: the available and yours looks are from the `booked` reference (light blue #8fbdd7, navy #476470, white inset ring); unavailable is the crossed grey circle. Busy windows are invented (only the near car's free afternoon and its free-until-15-Oct window are evidenced; a 3-day free window means pin 0's strip shows no unavailable dots in its first 68 h). They are anchored to the start of the current hour, so recordings match apart from clock labels. Pins are 15 solo plus 2 clusters; their layout beyond the references is invented.
- Cars per pin are invented, from six real models with their own photo, chips and plan (Corolla Hatchback, Corolla Hybrid, Prius Prime PHEV, RAV4 Hybrid, Ford Escape Hybrid, Nissan Kicks): 9 SUVs, 3 of them all-wheel drive. There is no van or cargo photo and no such car, so those chips match 0 cars. The placement of the photo on the card and the page is fitted per model. The `booked` reference is a Prius Prime with a badge; the mock keeps its own car.
- Change Time opens the start time sheet: an assumption, the real target was never tapped. For OPEN RETURN the chosen range is marked for 12 h from the start (assumption, no evidence). The Earliest/Latest Availability box shows only when times are set and free (assumption). Earliest is the free window's start, never before the current quarter; Latest is the next busy start. When the time overlaps a booking the disabled BOOK and its note stay and the busy box replaces the Earliest/Latest box (IMG_7639, busy-box.png). Assumptions: for a set return, the busy box's window is the set duration (the reference had an open return, 12 h), and line 2's end is start + that duration. The rule that past quarters are crossed grey only when the range is free is fitted to the references (the brief said "as in 7634/7637", but 7634, 7638 and 7639 show them free); it is an inference.
- The enabled BOOK VEHICLE letter-spacing was tightened to 1.1 px to match the references (both states).
- Vehicle page: only the top (to Change Time) is seen in the reference; Home Location, Vehicle Details and Contact Modo are estimated from the accessibility tree.
- Filters: the selected chip and checked box styles are invented (navy fill, white label or tick; nothing was toggled in the reference). The sheet's open and close motion is an estimate, and the filter map behind the backdrop is the fictional camera.
- Time sheet: measured from the reference (`time`); End Time opens the same sheet (same title), as on the device. Estimates: no subtitle in SET RETURN (none was captured), open/close and wheel motion, the wheel's fade and 3D curve. The date range starts 30 days back as seen; the end of the range (+60 days) and past times being selectable are assumptions. The wheel uses the system SF font (native scroll-snap lists, not the real UIDatePicker).
- OPEN RETURN hiding End Time is from the reference, and so is the Return by row staying visible. The header with both times set ("12 Oct at 3:00 PM → 12 Oct at 4:00 PM") has no reference: the text is tightened to 13 px to fit before the clear button; the real app may differ.
- The UNAVAILABLE label is Roboto 12 px caps in #cd2026, measured from IMG_7638; its width differs by a few points.
- Home Location in the real app is richer than the mock's text-only version: a mini map with a dark house pin, an expand button and a locate button, a place name above the station line and a collapsible "Home Location Description" row. Not implemented.
- Status bar time, battery and notch come from the shared frame and differ by design. Small text offsets (tab bar, a few POI labels, header baseline) remain.
